# Design direction

ParyatechOS should feel calm, capable, precise, and human. It is a high-frequency operational product, so clarity and scanability outrank decoration.

- **Hierarchy before density:** group clearly, then choose Compact, Standard, or Wide deliberately.
- **Operational emphasis:** prioritize exceptions, ownership, deadlines, money, and next actions.
- **Quiet surfaces:** use semantic surfaces/borders, not decorative containers.
- **Controlled softness:** sections generally 16px, cards 12px, controls 8–10px, chips fully rounded—always through semantic tokens. Capsule CTAs are exceptional.
- **Two fonts:** Onest for headings/titles; Public Sans for UI, body, labels, dates, IDs, and money. Use tabular numerals for aligned data.
- **Lucide icons:** support labels and comprehension; never replace unclear language.

Keep global navigation stable. Use responsive layout tokens. Prefer normal page scroll; sticky table headers for long data. Table rows are typically 56–64px by density, with pagination inside the table. Use structure-matching skeletons for dashboard/table loading.

Avoid unapproved gradients, glassmorphism, ornamental shadows, oversized empty space, random accents, cards around everything, competing primary actions, color-only status, unlabeled icon actions, and one-screen component inventions.
