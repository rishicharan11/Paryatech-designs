# Component guidelines

Reuse order: existing component → documented variant → composition → proposed variant → proposed component.

An approved component documents purpose/non-use, anatomy, slots, content, variants/sizes/density, relevant interaction/loading/empty/error states, keyboard/focus/screen-reader/target behavior, responsive overflow, tokens, visibility rules, examples, and anti-examples.

Reusable bases should be contentless where product content varies; keep realistic examples separate. Use one primary action per region. Confirm destructive actions proportionally. Tables use intended 56–64px density, right-aligned numbers, useful sticky headers, and internal pagination. Forms keep labels persistent and errors local. Skeletons match expected structure.
